Document Viewer architecture

The current browser-only viewer is a strong foundation. For a regulated platform such as banking, the recommended production design is a hybrid: keep this viewer, and add a conversion and security service inside the organization's own network.

Current architecture Strengths Production gaps Recommended architecture Comparison Migration plan Open questions Libraries

1. Current architecture: browser only

Every step runs in the user's browser. Files are never uploaded and no third-party service is involved.

2. Strengths

StrengthWhy it matters
Nothing leaves the browser; no Google or MicrosoftNo third-party data sharing; simpler privacy and vendor review

pdf.js for PDFThe most common business format gets Mozilla-grade accuracy

4. Recommended architecture: hybrid

A conversion and security service inside the organization's network prepares every document; the browser and mobile apps then show one accurate PDF version, while spreadsheets keep their interactive grid.

6. Migration plan

  1. Phase 1: POC as preview (done). Browser viewer for all 15 formats, compatibility test, device check.
  2. Phase 2: conversion service. Internal container with LibreOffice/Gotenberg; store a PDF version of every Office and TIFF document; the viewer shows the PDF and keeps the grid for Excel/CSV.
  3. Phase 3: security and compliance. Viewer on a separate domain in a sandboxed iframe, malware scan on upload, access checks, audit log, optional watermark.
  4. Phase 4: quality. Automated tests for all formats (Playwright), WCAG 2.1 AA audit, real-device testing on iOS and Android.
  5. Phase 5: mobile apps. Native viewers (PDFKit / PdfRenderer) on the same PDF versions.

7. Open questions for the team

  1. Must documents look exactly like the original (legal or regulatory), or is a readable preview enough?
  2. Can a conversion service run inside the organization's infrastructure (LibreOffice, usually in a container)?
  3. Are audit logging and watermarking required?
  4. Which browsers and devices must users have, and are native mobile apps in scope?
  5. Is a WCAG 2.1 AA accessibility audit required?
