2-week plan

One area a day. Each day I fix it on staging, make the same change on angular, test it with the checklist in Chrome, Firefox and Safari, push it to Stage and Angular, and update the checklist and this report. Each week ends with a review on Stage; PROD is updated after the review.

How the fixes are made

Every fix is a change to the viewer's code, never to anyone's documents. For each one:

  1. I find the setting in the file. A .docx, .xlsx or .pptx file is a zip of XML files; every color, border, frozen row or shape is a setting there (Microsoft's ECMA-376 format; MS-DOC, MS-XLS and MS-PPT for the old binary files).
  2. I find where the viewer reads that part of the document and see which setting it ignores.
  3. I write the code. JavaScript reads the setting and builds the page (HTML for text and tables, SVG for shapes and charts, canvas for PDF pages); CSS styles it (colors, fonts, borders, frozen rows, rotation). About 80–90% of each fix is JavaScript.
  4. I test it. I render the test pack, compare it with Word, Excel or PowerPoint, and re-run every automated test in Chrome, Firefox and Safari so nothing else breaks.
  5. I release it. I make the same change on the Angular branch, push to Stage and Angular, and update the checklist and this report. PROD is updated after review.

Example, Excel frozen rows: the sheet's XML says <pane ySplit="2" state="frozen"/>. My fix reads that and keeps the first two rows on top with CSS position: sticky. From then on every Excel file with frozen rows shows them correctly.

Will the fixes work for every document?

  • Yes, for the features we fix. The code is shared, so every file anyone opens gets the fix, not only the test files.
  • Features not fixed yet still show missing in any document that uses them, until their day in the plan is done.
  • Rare variations can still differ: an unusual shape outside the common 25–30, a font not installed on the reader's device (a look-alike is used), page breaks in long Word pages, corrupted or non-standard files.
  • Everyday business documents (reports, letters, statements, formatted spreadsheets, normal decks, PDFs, scans) already look right almost every time.
  • Best check: I will also test 5–10 real documents from reviewers (nothing confidential) the same way.
